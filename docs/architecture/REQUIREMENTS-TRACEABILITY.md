# Requirements & Invariants Traceability Matrix (RTM)

Maps every business invariant (`INV-01`–`INV-10`) and acceptance criterion (`AC-01`–`AC-12`) across all 5 layers of the workshop Trust Pyramid.

## 1. Invariant Enforcement Matrix

| Invariant | Domain Types / Rules (Layer 1) | App & Auth Boundaries (Layer 1) | DB Constraints & Transactions (Layer 2) | Automated Tests (Layer 2) | Runtime Verification (Layer 3) | Formal Model (Layer 4) |
| --- | --- | --- | --- | --- | --- | --- |
| **INV-01 — Financial consistency** (`committed <= allocated`) | `MoneyMinor`, `computeAvailableBudget`, `canCommitAmount` | `purchaseRequestService.decide` | `SELECT ... FOR UPDATE` on `cost_centers`; `CHECK (committed_budget_minor <= allocated_budget_minor)`; `UNIQUE (tenant_id, request_id)` | `tests/unit/domain.test.ts`, `tests/concurrency/approval-concurrency.test.ts`, `tests/properties/procurement.properties.test.ts` | `ph42:reproduce`, `verify:concurrency`, `verify:all`, `tests/e2e/procurement-approval.spec.ts` | `ProcurementApproval.tla` (`BudgetNotExceeded`, `CommitmentMatchesApprovedSum`) |
| **INV-02 — Non-negative availability** (`available >= 0`) | `computeAvailableBudget` throws/rejects negative | Route maps `insufficient-budget` -> `409 INSUFFICIENT_BUDGET` | `CHECK (committed_budget_minor >= 0 AND committed_budget_minor <= allocated_budget_minor)` | `tests/unit/domain.test.ts`, `tests/concurrency/approval-concurrency.test.ts`, `tests/properties/procurement.properties.test.ts` | `ph42:reproduce`, `verify:all` before/after DB snapshot | `ProcurementApproval.tla` (`NonNegativeAvailability`) |
| **INV-03 — Idempotency** (equivalent retries do not double-commit) | `canonicalSubmissionPayload`, `canonicalDecisionPayload` | `Idempotency-Key` required & validated (`keySchema`) | `PRIMARY KEY (tenant_id, idempotency_key)` on `decision_idempotency_keys`; `UNIQUE (tenant_id, idempotency_key)` on `purchase_requests` | `tests/integration/procurement.test.ts`, `tests/concurrency/approval-concurrency.test.ts`, `tests/properties/procurement.properties.test.ts` | `verify:concurrency`, `verify:all`, feature map `idempotent-retries.md` | `ProcurementApproval.tla` (`IdempotentReplayConsistent`) |
| **INV-04 — Payload consistency** (same key + different payload/actor -> 409) | Canonical field tuple comparison | Generic `409 IDEMPOTENCY_CONFLICT` with zero resource leakage | Persisted `actor_id`, `request_id`, `decision`, `reason`, `request_hash` | `tests/integration/procurement.test.ts`, `tests/security/isolation-and-auth.test.ts` | `verify:all`, feature map `idempotent-retries.md` | Explicitly out of TLA+ scope (documented in `formal/README.md`) |
| **INV-05 — Tenant isolation** (no cross-tenant reads or writes) | `TenantActor.tenantId` required on every domain check | Server-side session resolution; `z.strictObject` rejects client `tenantId`; `404 NOT_FOUND` on foreign IDs | Composite FKs `(tenant_id, id)` on `cost_centers`, `purchase_requests`, `financial_commitments`, `audit_events`, `decision_idempotency_keys` | `tests/security/isolation-and-auth.test.ts`, `tests/properties/procurement.properties.test.ts` | `tests/e2e/procurement-approval.spec.ts`, feature map `tenant-isolation.md` | Scope-bounded to single tenant cost center; multi-tenant verified at DB/HTTP layers |
| **INV-06 — Authorization** (role, non-self, limit, incl. replay) | `evaluateApprovalAuthority` | Enforced in route + application + BEFORE idempotency replay in repository | `memberships.role` CHECK, `approval_limit_minor` CHECK, `requester_id <> actor_id` | `tests/unit/domain.test.ts`, `tests/security/isolation-and-auth.test.ts` | `verify:all`, feature map `authorization.md` | Model assumes pre-authorized approvers; auth verified by security suite |
| **INV-07 — State machine integrity** (`PENDING -> APPROVED | REJECTED` only) | `canTransitionStatus`, `PurchaseStatus` union | Rejects terminal transitions (`409 INVALID_TRANSITION`) even with new key | `WHERE status = 'PENDING'` conditional update + `CHECK (status IN (...))` | `tests/unit/domain.test.ts`, `tests/integration/procurement.test.ts`, `tests/properties/procurement.properties.test.ts` | `verify:all`, feature map `purchase-request-approval.md` | `ProcurementApproval.tla` (`TerminalStateImmutable`) |
| **INV-08 — Audit consistency** (exact 1:1 durable event, no duplicates) | `AuditEventType` union | Audit endpoint restricted to `APPROVER`/`AUDITOR` | Written inside same PostgreSQL transaction as creation/decision; no write on replay | `tests/integration/procurement.test.ts`, `tests/concurrency/approval-concurrency.test.ts` | `tests/e2e/procurement-approval.spec.ts`, `verify:all` DB snapshot | `ProcurementApproval.tla` (`AuditMatchesApproved`) |
| **INV-09 — Atomicity** (request + budget + commitment + idempotency + audit) | Pure use-case ports requiring transactional repo | Single transaction boundary per write | Single PostgreSQL `transaction(...)` block | `tests/integration/procurement.test.ts` (forced audit constraint failure rollback) | `verify:all`, feature map `failure-recovery.md` | `ProcurementApproval.tla` (`CommitmentMatchesApprovedSum`, `AuditMatchesApproved`) |
| **INV-10 — Recoverability** (no invalid intermediate state after failure or timeout) | Explicit `DecisionResult` union | Clean rollback on pre-commit failure; safe replay on post-commit timeout | PostgreSQL ACID rollback + committed `decision_idempotency_keys` replay | `tests/integration/procurement.test.ts`, `tests/integration/approval-migration.test.ts` | `verify:all`, feature map `failure-recovery.md` | `ProcurementApproval.tla` (lost-response retry transitions) |
