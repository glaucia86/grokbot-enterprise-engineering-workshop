## Changes

The runnable VS-04 base already used a tenant/key constraint and an atomic insert with an audit event in the same transaction. Migration `0001` installs the constraint on a legacy database with clean data. It refuses duplicate tenant/key groups with a reconciliation message and preserves requests, audit events and the prior journal. The already protected baseline can upgrade and rerun without data changes.

Replay looks up the existing tenant/key in a separate READ COMMITTED statement and compares requester and normalized purchase fields. Equivalent requests recover the current representation even when a historical fingerprint differs. A conflicting actor or payload gets the established generic `409`. See the [instructor ADR](../adr/0001-idempotency-reference-solution.md).
